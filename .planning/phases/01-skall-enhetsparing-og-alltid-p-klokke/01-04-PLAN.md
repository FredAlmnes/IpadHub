<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone browser -> /auth/google/* | OAuth redirect parameters are attacker-controllable |
| Google -> Worker | id_token and token endpoint responses |
| phone browser -> /admin POST | state-changing forms (approve, revoke, logout) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-19 | Spoofing | OAuth login CSRF / replay | mitigate | random state + nonce in a signed 10-min HttpOnly cookie; callback verifies state and nonce; tested |
| T-01-20 | Spoofing | forged id_token | mitigate | jose jwtVerify against Google JWKS with issuer and audience = GOOGLE_CLIENT_ID, exp enforced; tests with wrong aud fail |
| T-01-21 | Elevation of privilege | allowlist bypass | mitigate | email_verified === true and exact lower-cased match against ADMIN_EMAILS; re-checked on every admin request |
| T-01-22 | Tampering | CSRF on approve/revoke/logout | mitigate | hono csrf() Origin check on all /admin POST + SameSite=Lax cookies; tested 403 |
| T-01-23 | Elevation of privilege | revoking/listing another user's devices | mitigate | every devices query filtered by session user_id; cross-user revoke returns 404 (tested) |
| T-01-24 | Tampering | XSS via device name or flash params | mitigate | hono/html auto-escaping; raw() only for compiled CSS and static SVG; tested with <script> name |
| T-01-25 | Information disclosure | secrets/tokens in logs | mitigate | no logging of code, tokens or id_token; client secret only in Worker secrets; no offline access requested in phase 1 |
| T-01-26 | Tampering | open redirect | mitigate | fixed redirect targets (/admin, /admin/login); redirect_uri derived from origin and enforced by Google's registered list |

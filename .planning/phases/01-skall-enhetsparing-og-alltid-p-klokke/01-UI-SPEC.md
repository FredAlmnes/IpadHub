## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap, stale dot gap |
| sm | 8px | Label-to-value gap inside a module slot |
| md | 16px | Default element spacing, admin card padding |
| lg | 24px | Admin section gap, module slot inner padding |
| xl | 32px | Gap between module slots (grid gap) |
| 2xl | 48px | iPad safe-area padding (all edges), admin top padding |
| 3xl | 64px | Gap between pairing heading and code |

Exceptions:
- Admin touch targets: minimum height 48px (a size floor, not a spacing token).
- Burn-in drift is a transform and does not consume layout spacing; the 48px safe padding guarantees nothing clips.
- Module slot hairline border is 1px.

## Typography

**[User] Restructured scale: 5 sizes, 2 weights (400, 600).** The scale is the usual four roles plus one intentional exception: Display-M (96px), a dedicated mid-large size shared by the night clock and the pairing code. Display-L (192px) is the day clock only. This keeps the scale coherent (each size has one clear job) while satisfying the user's request that the night clock be clearly smaller than the day clock (D-15).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 16px | 400 | 1.5 | Staleness text, module labels, offline marker text, admin body/helper text, inputs and list meta |
| Body | 24px | 400 | 1.5 | Week number, placeholder text, pairing instruction; admin page titles at weight 600 |
| Heading | 40px | 600 | 1.2 | Date line, pairing heading, future module headline numbers |
| Display-M | 96px | 400 | 1.0 | Night clock (dimmed) and pairing code |
| Display-L | 192px | 400 | 1.0 | Day clock (S1) only |

Rules:
- Clock is 24 h `HH:MM`, no seconds, `white-space: nowrap`. Compose from `Intl.DateTimeFormat.formatToParts` with `hourCycle: "h23"`, never `toLocaleTimeString` output **[Research]**.
- Display weight is 400 so large numerals stay calm; 600 is for headings and emphasis.
- Letter-spacing: Display-L -0.02em; pairing code +0.08em.
- Display-L scales `clamp(160px, 16vw, 192px)` (192 is the ceiling); Display-M is fixed 96px on both iPad sizes.
- **Pairing code [Discretion]:** Display-M (96px) because the code is 8 characters plus a hyphen (e.g. `K7QM-4TXD`, per RESEARCH Pattern 2). At 192px it would not fit 1180px; 96px is still readable at 1–2 m (each glyph ~70px tall).
- Admin: body 16px/1.5 weight 400, titles 24px/1.2 weight 600. Never below 16px (prevents iOS input zoom).

## Color

Dark theme only (D-02). One muted accent (D-05).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` | Page background on iPad (all views) and admin |
| Secondary (30%) | `#1C1C1E` | Admin cards, list rows, inputs. On iPad no fills (D-03): the share is carried by muted text `#8E8E93` and hairlines `#2C2C2E` |
| Accent (10%) | `#8FB8DE` (muted sky blue) **[User confirmed]** | See reserved list |
| Destructive | `#E5645A` | «Trekk tilbake» actions and their confirm button only |

Supporting neutrals (not additional hues): text primary `#F2F2F7`, text muted `#8E8E93`, hairline `#2C2C2E`.
- Night clock `#5A5A5A` **[Research]** (~3.2:1 on black). Intentionally dim, accepted exception to AA for the sleeping-room view.
- Stale content: same colors at `opacity: 0.4` (no new hue).

Accent reserved for (nothing else):
1. Primary button fill in admin («Godkjenn iPad»). «Logg inn med Google» follows Google branding instead.
2. Admin keyboard focus ring (2px outline, 2px offset).
3. «Koblet til» success check icon (pairing screen and admin approval result).
4. Waiting indicator dot on the pairing screen.
5. Later phases (not used in phase 1): «neste» event, «gå nå».

Not accent: staleness markers, offline marker, clock, date, module labels (grayscale by design).

## Layout and Screen Contracts

### S1 Dagvisning

Landscape only (D-01). Background `#000`, padding 48px (2xl) on all edges.

```
+------------------------------------------------------------+
|                                   [wifi-off Frakoblet]     |
|  14:32                 +-------------+ +-----------------+ |
|  mandag 19. oktober    | Buss        | | Vær             | |
|  Uke 43                +-------------+ +-----------------+ |
|                        +-------------+ +-----------------+ |
|                        | Kalender    | | E-post          | |
|                        +-------------+ +-----------------+ |
+------------------------------------------------------------+
```

**[Discretion] Clock dominance:** clock block in the left column (5/12 of content width), vertically centered; modules in the right 7/12 as a 2x2 grid with 32px (xl) gap, equal-height slots. Order: Buss, Vær (top), Kalender, E-post (bottom). Later phases only fill slots, the grid does not change.

Clock block (left aligned, gap sm 8px):
1. Time, Display-L (192/400), primary. Wrapped in `<time datetime>`.
2. Date, Heading (40/600), primary: «mandag 19. oktober» (lowercase, from `Intl` with `timeZone: "Europe/Oslo"`).
3. Week, Body (24/400), muted: «Uke 43» (ISO week computed from the Oslo calendar date) **[Research]**.

The clock ticks from local time and keeps running offline; it never waits for the server (DISP-02).

Module slot (placeholder, D-07), driven by snapshot status `not_configured`:
- 1px hairline `#2C2C2E`, radius 16px, no fill, padding lg (24px).
- Top-left: module label, Label, muted: «Buss», «Vær», «Kalender», «E-post».
- Center: Body, muted: «Kommer snart».
- Bottom-left: freshness line, Label, muted: «Ingen data ennå».
- Every slot is wrapped in `ModuleFrame` with its own ErrorBoundary: a render or data failure only affects that slot (DISP-06).

### Module states (contract for every slot, now and later)

**[Discretion] Staleness and offline (DISP-05), no banners.** Staleness is derived from server data: `age = (serverTime - fetchedAt) + local elapsed since receipt`; stale when `age > staleAfterSec` (threshold owned by the server per module) or `status === "error"` **[Research]**.

| State | Visual | Freshness line copy |
|-------|--------|---------------------|
| Fresh | Normal content | «Oppdatert 14:32» (Label, muted; Oslo time of `fetchedAt`) |
| Stale | Content at 40% opacity; 8px hollow circle (1.5px stroke, muted) before the text | «Oppdatert 14:32 · utdatert» |
| Error, no cached data | Center text «Utilgjengelig» (Body, muted) | «Sist oppdatert 14:32» or «Aldri oppdatert» |
| Error, with cached data | Treated as Stale | as Stale |
| Not configured (phase 1) | Placeholder content | «Ingen data ennå» |

- If `fetchedAt` is older than 24 h show «Oppdatert i går 14:32» or weekday + time.
- **Global offline marker [Research]:** shown when no successful snapshot has arrived for more than 2 poll intervals (60 s), not based on `navigator.onLine` (unreliable on iOS). Top-right at the padding edge: Lucide `wifi-off` 24px + Label «Frakoblet», muted. No bar, no color change. Disappears on the first successful snapshot. Last cached data stays visible (dimmed once stale).
- Polling: snapshot every 30 s; immediate refetch on `visibilitychange` and `online`.

### S2 Nattvisning (D-14..D-17)

- Active 23:00–06:00 Europe/Oslo (from `snapshot.config`, hard-coded fallback so it works offline). Wrap-around window; decided on the Oslo clock so DST is correct.
- Background `#000`. Only the clock: **Display-M (96/400), `#5A5A5A`** **[User]**, centered. Date, week, placeholders, freshness and offline marker are hidden (D-15). Modules stay mounted (hidden with `visibility: hidden` after fade) to avoid refetch flicker **[Research]**.
- Crossfade day <-> night: **3000 ms** opacity ease-in-out **[Research]** (D-16).
- **Tap-to-wake (D-17):** any `pointerdown` during night fades in the day view over 600 ms, holds **90 s** **[Research]** (a further tap resets the timer), then fades back over 3000 ms. No visible hint. Requires Guided Access Touch = on (see checklist).

### S3 Paringsskjerm (SEC-01, D-12, D-13)

**[Discretion] Direction: iPad shows the code, owner approves on phone** (Apple TV pattern; cookie is set by the poll response inside the installed PWA, per RESEARCH Pattern 2). No keyboard ever appears on the iPad.

- Centered column on `#000`, no clock, no module slots.
- Heading (40/600), primary: «Koble til denne iPaden»
- 64px (3xl) gap.
- Code: **Display-M (96/400, +0.08em tracking)**, primary, **8 characters in two groups of four joined by a hyphen** (`K7QM-4TXD`), uppercase, alphabet `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (no 0/O/1/I/L) **[Research]**.
- 48px gap, then Body, muted: «Åpne /admin på mobilen og skriv inn koden.» (show the real host).
- Bottom of column: 8px accent dot (2 s opacity pulse 1.0–0.4) + Label muted «Venter på godkjenning».
- Behaviour **[Research]**: `POST /api/pair/start` on mount; code lifetime 10 min; poll `POST /api/pair/poll` every 3 s with `pollSecret` kept in memory and `sessionStorage` (a reload resumes the same code). On `expired`, fetch a new code silently and swap it, no error shown.
- States:
  - Waiting: as above.
  - Approved: dot becomes accent `check` + Label «Koblet til», 1.5 s, then 600 ms fade to S1. Token is never shown or handled in JS.
  - Network/server error (including 5xx and 429): Label muted «Ingen kontakt med serveren. Prøver igjen …» replaces the waiting line; code stays visible; retry with backoff.
  - Un-pair: only an exact HTTP 401 from `/api/snapshot` switches to this screen, immediately with a fresh code and no message (D-12). Network failure, 5xx and 429 never un-pair. After revoke, the screen appears within one poll interval (30 s) or on the next `visibilitychange`.
- Only auth UI on the iPad; there is never a login screen (SEC-01).

### S4 Admin (/admin, phone portrait; D-08..D-11)

Server-rendered, single column, max-width 480px centered, page padding md (16px), top padding 2xl. Background `#000`, cards `#1C1C1E` radius 16px padding md. Core flows work without JS (form POST + redirect; CSRF via Origin check). Inputs 16px.

**/admin/login**
- Title (24/600) «IpadHub». Body muted: «Logg inn for å koble til og administrere iPader.»
- Button «Logg inn med Google», full width, 48px, Google brand style (only light element; allowed brand exception).
- Not on allowlist: «Denne Google-kontoen har ikke tilgang.» (destructive-colored text above the button). Other failure: «Innloggingen mislyktes. Prøv igjen.»

**/admin (30-day session, D-10)**
1. Header row: title «IpadHub» (24/600); «Logg ut» text button with `log-out` icon right (48px target). Link «Oppsett av iPaden» to /admin/oppsett (Label size, muted, 48px target).
2. Card «Koble til ny iPad» (title 24/600, helper «Skriv inn koden som vises på iPaden.»):
   - Code input, label «Kode», accepts `K7QM-4TXD` or `K7QM4TXD` (normalized to uppercase, hyphen optional), `autocapitalize="characters"`, `autocomplete="off"`, 16px text, letter-spacing 0.2em, height 48px.
   - **[User] Name input**, label «Navn på enheten», **editable, pre-filled with value «Stue-iPad»** (a real value, not a placeholder).
   - Primary button «Godkjenn iPad» (accent fill, `#000` text, 48px, full width).
   - Success: accent `check` + «Koblet til: {navn}». Bad/expired code: «Koden stemmer ikke eller er utløpt. Sjekk koden på iPaden og prøv igjen.»
3. Section «Enheter» (24/600). Row per device (card): name (16/600); meta (16/400 muted) «Sist sett for 3 min siden» (under 1 h), «Sist sett i dag 14:32», «Sist sett i går 21:05», or «Sist sett 12. okt. 09:10»; «Trekk tilbake» button (outlined, destructive text and 1px destructive border, 48px, full width).
4. Empty: heading «Ingen iPader ennå», body «Når du har koblet til en iPad, dukker den opp her.»

**Revoke confirmation (SEC-03):** «Trekk tilbake» opens `/admin/devices/:id/revoke` (server-rendered, no JS): «Trekk tilbake «Stue-iPad»? iPaden mister tilgangen med en gang og viser paringskoden igjen.» Buttons «Trekk tilbake» (destructive fill `#E5645A`, `#000` text) and «Behold iPaden» (outlined, muted). Success returns to the list with ««Stue-iPad» er trukket tilbake.»; revoked devices leave the list.

**/admin/oppsett [User confirmed as decision] (DISP-10):** admin-styled, mobile-readable page «Oppsett av iPaden» holding the setup checklist (copy below). It is the canonical location; `docs/ipad-setup.md` in the repo mirrors the same text per RESEARCH. Static text, numbered steps, no saved checkbox state, reachable only when logged in.

Other states: expired admin session redirects to login silently; server error: «Noe gikk galt. Prøv igjen om litt.»

## Motion and Always-on Behaviour

| Element | Spec |
|---------|------|
| Day/night crossfade | 3000 ms, opacity, ease-in-out (D-16) |
| Tap-to-wake | 600 ms in, hold 90 s, 3000 ms out |
| Burn-in drift, night clock (DISP-08) **[Research]** | Every 60 s move to a new position along a slow path within safe margins; glide via `transform: translate()` with a ~50 s transition. Orbit up to ±96px x and ±64px y from center, always inside the 48px safe area |
| Burn-in drift, day layout and pairing screen **[Discretion, adjusts RESEARCH's 1–2px]** | Every 5 min shift the whole content layer by a new offset within ±8px x/y (multiples of 4) with a 30 s glide. RESEARCH proposed 1–2px as an assumed cosmetic value; 8px is a stronger burn-in guard and still imperceptible |
| Clock digit change | No animation |
| Pairing waiting dot | 2 s opacity pulse |
| Press state (admin) | 80% opacity; no hover states (touch only) |

Reliability behaviours that affect what the screen shows **[Research]**:
- **Wake Lock:** re-acquire on `visibilitychange` and via a 60 s heartbeat. Failure is silent (no UI).
- **Daily reload:** 03:30 Europe/Oslo, once per Oslo date (flag keyed by date). Because the night view is active then, the reload is invisible. If a tap-to-wake window is open, defer until it ends. Screen background and launch splash are `#000` so no white flash.
- **Version reload:** if snapshot `version` differs from the client build id, reload; guard: at most one version-triggered reload per 10 min (`localStorage` timestamp).
- **Watchdog:** no successful snapshot for 15 min while `navigator.onLine !== false` -> guarded reload. Reloads show nothing but the black background and then the shell.
- **Service worker:** shell is served network-first with cached fallback so a reload during a Wi-Fi outage shows the dashboard with stale/offline indicators instead of a browser error page. `/api/*`, `/admin*`, `/auth/*` are never cached.

### Setup checklist copy for /admin/oppsett (DISP-10, D-18)

Title «Oppsett av iPaden». Numbered steps, one or two sentences each:
1. Oppdater: «Bruk iPadOS 18.4 eller nyere. Det trengs for at skjermen kan holde seg våken i hjemskjerm-appen.»
2. Hjemskjerm: «Åpne siden i Safari, trykk Del og velg Legg til på Hjem-skjerm. Start deretter appen fra ikonet, ikke fra Safari.»
3. Parring: «Åpne appen fra hjemskjermen og finn koden på skjermen. Godkjenn den her på mobilen. Legger du appen til på nytt, må du pare på nytt.»
4. Autolås: «Innstillinger > Skjerm og lysstyrke > Autolås > Aldri.»
5. Veiledet tilgang: «Innstillinger > Tilgjengelighet > Veiledet tilgang. Slå på, sett kode og start med trippeltrykk på sideknappen i appen. La Berøring stå på (trengs for å vekke skjermen om natten) og sett Autolås for skjerm til Aldri.»
6. Lading: «La iPaden stå i lader hele tiden. Bruk optimalisert lading hvis modellen har det, og unngå sol, varme og tykke deksler.»
7. Lysstyrke om natten: «Snarveier > Automatisering > Ny automasjon > Tid på døgnet. Kl. 23:00: Angi lysstyrke lavt. Kl. 06:00: Angi lysstyrke høyt. Velg Kjør umiddelbart.» (D-18)
8. Forstyrr ikke: «Slå på en fokusmodus som skjuler varsler, og unngå lav strømforbruk-modus. Etter en iPadOS-oppdatering: sjekk punkt 4 og 5 på nytt.»
9. Hvis koden dukker opp: «Åpne /admin på mobilen og godkjenn den. Trekk tilbake mistede enheter under Enheter.»

## Accessibility and Robustness

- Admin: visible labels on all inputs; accent focus ring; text contrast >= 4.5:1 on `#000` and `#1C1C1E` (primary `#F2F2F7`, muted `#8E8E93`).
- iPad: muted `#8E8E93` on black ~6.2:1; night clock deliberately ~3.2:1.
- `lang="nb"`; iPad SPA: `viewport-fit=cover, user-scalable=no`, `user-select: none`, `-webkit-touch-callout: none`. Admin keeps zoom enabled.
- Meta **[Research]**: `apple-mobile-web-app-capable=yes`, `apple-mobile-web-app-status-bar-style=black`, `theme-color=#000000`, manifest `display: standalone`, `orientation: landscape`, background/theme `#000000`, 180px apple-touch-icon, name «IpadHub».
